<task type="auto">
  <name>Task 1: Bronze models</name>
  <files>src/emeye/db/models.py</files>
  <read_first>.planning/phases/02-ingestion/02-CONTEXT.md, docs/ARCHITECTURE.md</read_first>
  <action>
Add two models to `emeye.db.models`.

`RawDocument` (`raw_document`):
- `id` bigint identity PK
- `source` text not null — e.g. "beatport", "deezer"
- `endpoint` text not null — logical endpoint, not the full URL
- `params` JSONB not null default '{}' — request parameters
- `params_hash` text not null — sha256 of canonical-JSON params, so the unique
  index does not depend on JSONB equality semantics
- `url` text not null
- `fetched_at` timestamptz not null
- `http_status` smallint not null
- `payload` JSONB — extracted JSON (D-01)
- `raw_body` text — the surrounding markup when the source shipped HTML (D-02).
  Bronze must stay replayable when the *extraction* was wrong, not just the parse
- `content_hash` text not null — sha256 of the bytes as received
- `content_type` text
- `elapsed_ms` integer

Indexes: unique on `(source, endpoint, params_hash, fetched_at)` per D-04;
btree on `(source, endpoint, fetched_at desc)` for "latest document" lookups;
btree on `content_hash` for the cache check.

**`content_hash` must not be unique.** The same chart content on two days is two
facts. Collapsing them would silently destroy the chart time series, which is
the one thing this project cannot rebuild.

`IngestRun` (`ingest_run`):
- `id` bigint identity PK
- `source`, `job_name` text not null
- `status` text not null — `started` | `succeeded` | `failed` | `skipped_cache` (D-14)
- `started_at` timestamptz not null, `finished_at` timestamptz null
- `items_fetched`, `items_written`, `cache_hits`, `cache_misses` integer not null default 0
- `error_type` text, `error_message` text, `traceback` text
- `params` JSONB not null default '{}'

Index on `(source, started_at desc)` for `emeye status`.

Use timezone-aware columns throughout — ruff's DTZ rules are enabled and naive
timestamps in a time-series warehouse are a silent correctness bug.
  </action>
  <verify>uv run python -c "from emeye.db import models; print(models.RawDocument.__tablename__, models.IngestRun.__tablename__)"</verify>
  <acceptance_criteria>
    - content_hash has a non-unique index
    - The unique constraint includes fetched_at
    - Every timestamp column is timezone-aware
    - raw_body exists alongside payload
  </acceptance_criteria>

<task type="auto">
  <name>Task 3: The bronze store</name>
  <files>src/emeye/bronze/__init__.py, src/emeye/bronze/store.py</files>
  <read_first>src/emeye/db/engine.py, src/emeye/logging.py</read_first>
  <action>
`store.py` is the **only** module that writes `raw_document`. Everything else
goes through it, so the invariants live in one reviewable place.

API:
- `canonical_params_hash(params: dict) -> str` — sorted-key canonical JSON,
  then sha256. Deterministic across processes and Python versions.
- `content_hash(body: bytes) -> str` — sha256 hex.
- `store_document(...) -> RawDocument` — writes one row inside `session_scope`.
  Accepts already-extracted JSON plus optional raw body.
- `latest_document(source, endpoint, params) -> RawDocument | None` — the most
  recent row for that request shape.
- `has_content(content_hash) -> bool` — for the cache check.
- `iter_documents(source, endpoint=None, since=None) -> Iterator[RawDocument]` —
  the replay path plan 02-03 uses for reparse.

Log every write with source, endpoint, status, content_hash prefix and payload
size, per CLAUDE.md's logging rule.

No UPDATE or DELETE helpers. Not "discouraged" — absent, so there is nothing to
call by accident.
  </action>
  <verify>uv run pytest tests/unit/test_bronze_store.py -q</verify>
  <acceptance_criteria>
    - store.py contains no UPDATE or DELETE statement
    - canonical_params_hash is order-independent for equivalent dicts
    - Every write is logged with source, endpoint and content hash
  </acceptance_criteria>
  <done>The store writes and reads bronze rows through one narrow API.</done>
</task>
