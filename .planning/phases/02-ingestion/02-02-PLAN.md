<objective>
The politeness layer: one client through which all outbound HTTP passes, with
robots.txt, rate limiting, backoff and opt-in gating enforced centrally.

Purpose: CLAUDE.md's legal and ethical posture is binding, and a rule enforced
per-source is a rule that will eventually be forgotten in one source. This makes
polite behaviour structural — difficult to bypass by accident and impossible to
bypass by configuration.
Output: a client that is safe to hand to any future connector.
</objective>

<task type="auto">
  <name>Task 1: robots.txt as a first-class component</name>
  <files>src/emeye/http/robots.py</files>
  <read_first>CLAUDE.md, docs/DATA-SOURCES.md</read_first>
  <action>
`RobotsPolicy` wrapping `urllib.robotparser.RobotFileParser`:

- `is_allowed(url, user_agent) -> bool`
- fetches `robots.txt` per host, caches the parsed result with a TTL from
  settings (default 24h)
- **fails closed** (D-08): if robots.txt cannot be fetched or parsed, the answer
  is *no*. A source that will not serve robots.txt does not get crawled. This is
  the opposite of `RobotFileParser`'s default, which treats unreachable as
  allow-all — do not inherit that behaviour, and say why in a comment.
- honours `Crawl-delay` when present, taking the stricter of it and our
  configured rate
- a 404 robots.txt **is** a valid "no rules" answer and permits crawling; a
  timeout, 5xx or connection error is not

Fetch robots.txt with a plain short-timeout httpx call, not through the rate-limited
client — otherwise the client and the policy are mutually recursive.

Log every decision at debug, and every *denial* at warning. A silent denial
looks identical to a broken collector.
  </action>
  <verify>uv run pytest tests/unit/test_robots.py -q</verify>
  <acceptance_criteria>
    - Unreachable robots.txt yields is_allowed() False
    - 404 robots.txt yields True
    - Crawl-delay is respected when stricter than config
    - Results are cached per host with a TTL
  </acceptance_criteria>
  <done>The checker is cached, TTL'd and fails closed.</done>
</task>

<task type="auto">
  <name>Task 2: Per-host rate limiter</name>
  <files>src/emeye/http/limiter.py, src/emeye/config.py</files>
  <read_first>src/emeye/config.py</read_first>
  <action>
A per-host limiter enforcing a minimum interval between requests, defaulting to
`settings.default_rate_limit_per_sec` (1.0) with per-host overrides for sources
that document a different limit (MusicBrainz is 1 req/s and says so).

Add to settings: `robots_cache_ttl_seconds` (86400), `rate_limit_jitter_seconds`
(0.0–0.5), and a `per_host_rate_limits` mapping.

Sleep the remainder of the interval plus jitter. Jitter matters: a perfectly
periodic request pattern is both more detectable and less polite than a slightly
irregular one.

The limiter must be safe to call from the scheduler and the CLI in the same
process. Use a lock keyed by host.
  </action>
  <verify>uv run pytest tests/unit/test_limiter.py -q</verify>
  <acceptance_criteria>
    - Two consecutive calls for one host are spaced by >= the interval
    - Different hosts do not block each other
    - Jitter is applied and bounded
    - New settings appear in .env.example
  </acceptance_criteria>
  <done>Requests to a host are spaced; hosts are independent.</done>
</task>

<task type="auto">
  <name>Task 3: The client</name>
  <files>src/emeye/http/client.py, src/emeye/http/__init__.py</files>
  <read_first>src/emeye/http/robots.py, src/emeye/http/limiter.py, src/emeye/config.py</read_first>
  <action>
`PoliteClient`, the single outbound HTTP path:

- constructed **for a named source**, and raises immediately if that source's
  `enable_<source>` flag is False (REQ-23). Gating lives here, not in the
  caller, so a collector cannot collect just because someone called it.
- sets the configured `User-Agent` on every request. No browser impersonation,
  ever — assert the configured value is used rather than trusting it
- consults `RobotsPolicy` before every request; a denial raises a distinct
  `RobotsDenied` exception, never a silent skip
- applies the rate limiter before every request
- retries via `tenacity`: exponential backoff with jitter, capped, max attempts
  from settings; retries on connect errors, timeouts and 5xx; **never** retries
  4xx other than 429
- on 429, honours `Retry-After` **absolutely**, including values longer than the
  configured timeout (D-09). A 429 is the upstream telling us we got it wrong,
  and overriding it with our own shorter backoff is exactly the behaviour the
  collection posture forbids
- returns a small result object carrying status, body bytes, headers, elapsed
  time and the resolved URL — the shape `bronze.store` needs

Export `RobotsDenied`, `SourceDisabled` and `PoliteClient` only. Nothing outside
`emeye/http` may construct an `httpx.Client`; a test enforces this.
  </action>
  <verify>uv run pytest tests/unit/test_http_client.py -q</verify>
  <acceptance_criteria>
    - Constructing for a disabled source raises SourceDisabled
    - A robots denial raises RobotsDenied rather than returning None
    - Retry-After longer than the timeout is still honoured
    - 404 is not retried; 503 is
    - grep finds no httpx.Client outside src/emeye/http/
  </acceptance_criteria>
  <done>All outbound HTTP is polite, gated and centrally controlled.</done>
</task>
