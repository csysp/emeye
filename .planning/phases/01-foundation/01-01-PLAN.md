<objective>
Stand up the Python project skeleton: packaging, configuration, logging, the CLI
surface, and the database engine seam that every later phase attaches to.

Purpose: this is the spine. Phase 2's collectors, Phase 6's dbt invocation and
Phase 8's UI all hang off the config object, the CLI group registry and the
engine factory created here. Getting the seams right now is cheaper than
retrofitting them across eight phases.
Output: an installable `emeye` package with a working CLI that does nothing yet,
and a settings object that fails loudly on misconfiguration.
</objective>

<task type="auto">
  <name>Task 2: Settings as the single source of environment truth</name>
  <files>src/emeye/config.py</files>
  <read_first>.planning/phases/01-foundation/01-CONTEXT.md, docs/ARCHITECTURE.md</read_first>
  <action>
Implement `Settings(BaseSettings)` with `env_prefix="EMEYE_"`, reading `.env`,
covering:

- Database: `postgres_host`, `postgres_port` (5432), `postgres_db`, `postgres_user`,
  `postgres_password` (`SecretStr`), plus a computed `database_url` property that
  renders a SQLAlchemy URL. `postgres_password` has NO default — a missing value
  must fail.
- HTTP politeness: `user_agent` (required, no default — it must carry a real
  contact address), `default_rate_limit_per_sec` (1.0), `http_timeout_seconds` (30),
  `max_retries` (5).
- Paths: `data_dir` (`/data`), `export_dir` (`/data/exports`).
- Source enable flags: `enable_beatport`, `enable_musicbrainz`, `enable_discogs`,
  `enable_deezer`, `enable_lastfm`, `enable_listenbrainz` — **all default False**
  per D-07, so merging a collector never starts collection.
- Source credentials, all Optional and defaulting to None: `discogs_token`,
  `lastfm_api_key` (both `SecretStr`).
- `log_level` ("INFO"), `log_json` (Optional[bool], None = auto-detect by TTY).

Expose `get_settings()` cached with `functools.lru_cache`. Nothing else in the
codebase may read `os.environ` — this is the only place.

Validation errors must name the offending variable. Do not catch
`ValidationError` and re-raise something vaguer.
  </action>
  <verify>uv run python -c "from emeye.config import get_settings; get_settings()"</verify>
  <acceptance_criteria>
    - config.py contains 'env_prefix' set to "EMEYE_"
    - Every enable_* flag defaults to False
    - postgres_password and user_agent have no default value
    - grep for 'os.environ' and 'os.getenv' across src/ matches only config.py
  </acceptance_criteria>
  <done>Settings load from env/.env; a missing required var raises an error naming it.</done>
</task>

  <action>
Create a SQLAlchemy 2.0 engine factory reading `settings.database_url`, with
`pool_pre_ping=True` and a `session_scope()` context manager that commits on
success and rolls back on exception.

Engine creation must be lazy and cached — **no engine is constructed at import
time** (D-13). A module-level `create_engine(...)` call is a defect: it makes
every test and every `--help` invocation depend on a reachable database.

Export a `check_connection()` helper returning a bool, for `emeye status` in
Phase 2 to use.
  </action>
  <verify>uv run python -c "import emeye.db.engine"  # must not attempt to connect</verify>
  <acceptance_criteria>
    - engine.py has no module-level create_engine() call
    - session_scope rolls back on exception (covered by a unit test in 01-03)
    - importing emeye.db.engine with no database running succeeds
  </acceptance_criteria>
  <done>The module imports cleanly with no database present; the engine builds only on first use.</done>
